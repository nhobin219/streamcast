This minor release is breaking. It makes one FastAPI broker the only way to run streamcast, lets the inbox own its pause state, and stops an outbox from dropping a row when the broker fails to commit it.

- **One broker:** `streamcast.create_app(config=None, *, streams=())`, configured by `BrokerConfig`, serves static and managed streams under one lifespan. `serve()`, `streamcast.asgi`, the `streamcast.broker` module, the `asgi`/`broker` extras and `docs/BROKER.md` are removed, with no shim; FastAPI and uvicorn are normal dependencies. Run it under uvicorn with one worker and lifespan on. Migration steps are in the CHANGELOG.
- **Inbox owns its pause:** `initially_paused` is removed. `inbox(..., on_pause_change=callback)` reports every pause and resume, and the starting state before `inbox()` returns. Startup pauses at or above a high bound and starts active below both; a pause ends only below both low-water marks. See `docs/API.md`.
- **Outbox no longer drops rows:** a `commit_failed` reply now raises `CommitFailed` (not a `Rejected`); the outbox backs off, reconnects and resends.
- `BrokerConfig(subscriber_yield_every=64)` bounds how long one subscriber's send loop runs before yielding; 64 is provisional until measured (#194).

No wire or table migration is required.
