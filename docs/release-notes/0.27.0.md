This minor release is breaking. It separates a stream's definition from the runtime that serves it, and makes the managed control API declarative.

- **Definitions are data:** `Stream` is now a frozen `spec: StreamSpec` plus `storage: Storage` definition. Both are validated pydantic models that reject unknown fields, and storage credentials are never serialized. The runtime class is `StreamHandle`, with no compatibility alias. Open one with `StreamHandle.open(stream, initialization="open_existing")`, or pass `create_if_absent` or `restore_published` explicitly. Neither of those overwrites an existing replica with an empty stream.
- **Broker configuration:** `create_app(streams=...)` takes opened handles. Queue limits and `replicate` move from `BrokerConfig` onto each stream. `BrokerConfig(storage_profiles={name: Storage(...)})` replaces `StorageProfile`, and storage roots must be absolute.
- **Declarative control:** each managed stream has one bounded pending intent, and its declared state survives a broker restart. `PUT /streams/{name}/schema` replaces `POST .../migrations`. Control PUT takes a flat `StreamSpec`, and GET returns `{spec, storage}`.
- **Registry upgrade:** the registry moves to v3. Run `upgrade_registry(config)` once while the broker is stopped. It keeps a backup for downgrade, which loses changes made after the upgrade.
- **Client:** `Outbox.pending()` is renamed `pending_rows()`. Also new: `Outbox.pending_bytes()`, outbox backlog visibility (`backlog_after_s`, `on_backlog_change`) and an inbox receiver-error callback.
- Requires pydantic >= 2.11.

Migration steps are in the CHANGELOG.
